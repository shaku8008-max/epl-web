# EPL Predictor Theme

- **Colour roles:** `ink` (`#1b2433`) is all text and UI chrome. `edge` is the near-black structural border. `border` (`#d9e0ea`) is the soft row-level rule. `rule-strong` is the stronger chart/table rule. `surface` is the page background (`#f6f8fb`), `white` is the default card surface, and `tint` is for nested panels, state messages, hover states, and the footer. Outcome colours, better/worse colours and their soft tints, and the Lean, Neural, and Linear goals model colours remain distinct data signals.
- **Chrome rule:** near-black is UI chrome only. Never recolour outcome bars, outcome labels, table data, better/worse states, or model colours. Violet is not used.
- **Radius:** cards use `rounded-card` (`1rem`); buttons and tabs use `rounded-full` pills; inputs, selects, tooltips, and compact labels use `rounded-button` (`0.625rem`); existing status and outcome pills use `rounded-full`.
- **Borders:** `border-edge` marks structural lines: cards, controls, header/footer rules, card dividers, and summary/table outer rules. `border-border` remains for row separators, table headers, chart gridlines/axes, waterfall steps, stats column rules, and empty outcome tracks.
- **Buttons:** `Button` and `LinkButton` share primary, secondary, and `cta` variants. Primary is near-black filled with white text and a lighter near-black hover; secondary is white with a near-black border and ink text. The CTA is a label-sized white pill with an ink dot that fills the pill on mouse hover or keyboard focus, while its label reveals with an arrow. Touch devices show that filled state permanently; reduced motion switches instantly. Use CTA for a main action or a link to another page, with no more than two visible at once.
- **Cards:** `Card` defaults to a white surface; use `variant="tint"` only for nested panels or state surfaces.
- **Tabs and links:** every nav item is a bordered pill. Active tabs are near-black filled pills; inactive tabs are white with an ink border and fill near-black on hover, with no CTA dot or arrow. The model order is Track record, Lean, Neural network, Linear goals, Season outlook, with the outlook pushed right from `sm` upward. Inline links are ink, underlined, and use an ink decoration.
- **CTA locations:** CTA is used for Try a matchup (track record), See the track record and Explore the models (documentation), the selected model's predictions (model explorer), See how this model has done (Lean, Neural, and Linear goals), View scoreboard (Jev), Back to track record (not found), Try again (error), Refresh data (refresh), Add bet (journal), and the inactive Season outlook model tab. Keep low-priority and in-place actions secondary, including Back to Jev, refresh secondary states, and table/chart controls.
- **Season outlook tab:** when inactive it uses the CTA hover/focus reveal on mouse and keyboard, but stays white with a static arrow on touch; when active it is a normal filled tab with no dot or animation.
- **CTA details:** the resting CTA dot reserves its own inline space before the label, so it cannot overlap text. Win-rate chips keep the count on one line and place the percentage on a second, smaller muted line.
- **CTA layering:** the dot lives in the label row and the fill is a `clip-path` layer anchored to that dot slot, so the dot cannot overlap text.
- **Typography:** Archivo is used for text and headings. DM Mono with tabular numbers is used for figures.
- **Motion:** Existing 200–700ms ease-out transitions and animations remain, with capped stagger. `prefers-reduced-motion` overrides are respected.
- **Mobile:** Design for about 380px first. Interactive controls target 48px. Wide tables scroll sideways rather than compressing their columns.
- **Tone:** Honest and hedged. This is a learning project, not betting advice; never imply a model beats the bookmaker.
- **Model stack:** The documentation page shows a desktop/tablet-only live-count ModelStack with fanned cards linking to the Lean, Neural network, and Linear goals pages. It has no rank labels, and uses model colours only through `modelColour()`.
- **Do:** Keep labels beside colour signals, preserve data roles, and use the shared button styles. **Don’t:** add violet, make colour the only signal, recolour outcome/model colours, add a featured/best model badge, or imply predictive superiority.
